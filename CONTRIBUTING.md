# Contributing

## Workflow

1. Start from the latest `main` branch.
2. Create a focused branch such as `feature/monthly-budget` or `fix/category-totals`.
3. Make small, descriptive commits.
4. Run the project's checks before pushing.
5. Open a pull request that explains what changed and how it was verified.

## Commit messages

Use a short, action-oriented subject. Examples:

- `Add monthly budget model`
- `Fix category total rounding`
- `Document local setup`

## Pull requests

Pull requests should include:

- A concise summary of the change.
- Testing or verification notes.
- Screenshots for visible interface changes.
- Any follow-up work that is intentionally out of scope.

## Security and privacy

Do not commit secrets, production data, bank exports, or personally identifiable financial information. Use anonymized sample data for development and tests.
